Streams applications are organized around *domains*. A domain owns the stream definitions and the PHP that registers UI for them. The SDK conventions exist so that an agent or engineer can predict where a piece of an application lives from the domain it belongs to.

## Stream definitions

Stream definitions are plain JSON files at the application root, one file per stream. The filename is the stream id.

```text
streams/
    files.json
    blog_posts.json
    products.json
```

`make:stream` and `make:table` write here. Definitions reference the [stream definition schema](/docs/sdk/stream-schema), so editors validate them.

## The `app/Streams` domain registry

Generated UI lives next to the domain it serves, under `app/Streams` (configurable with `streams.sdk.tables_dir` and `streams.sdk.tables_path`). The registry is a PHP file that maps stream ids to flags, and domain components live beside it:

```text
app/Streams/
    tables.php            # registry written by make:table
    tables/
        orders.php        # larger table setups may be extracted here
```

`make:table --panel` registers the table in the application panel; `--page` registers a public page. The registry keeps those registrations in one place per domain instead of scattering panel wiring through service providers.

## Domains, not buckets

Keep the pieces of one domain together:

```text
streams/products.json        # the domain's data shape
app/Streams/products/        # the domain's Streams UI (panel resources)
app/Streams/tables.php       # one line per product table registration
```

Resist a single `app/Streams` bucket for all tables when a domain accumulates several; mirror the domain in the directory name.

## Classes

Follow Laravel conventions for PHP classes. The domain's stream id is `snake_case`; table and component handles are derived from it as `PascalCase` for class names and `kebab-case` for handles.

## Naming

- Stream ids and files: `snake_case`.
- Table ids passed to `make:table`: `snake_case` (validated: lowercase letters, numbers, underscores).
- Panels and pages: registered from the flags above, not by convention magic.

## Generated vs. authored

Anything the SDK generates is marked `Generated by streams/sdk` in a `$comment`. Do not edit generated artifacts; regenerate them and commit the new output. The catalog in `resources/catalog` of the SDK package is generated the same way and verified by the [catalog drift test](/docs/sdk/catalog) in CI.
